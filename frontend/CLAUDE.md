# Frontend — Next.js (`mps-aj-social-insights-portal`)

Read the root `CLAUDE.md` first. This file adds frontend-specific rules.

## Stack
- **Next.js 16** (App Router, Turbopack), **React 19**, **TypeScript** (`strict`)
- **pnpm** for packages
- **Tailwind CSS v4** + **shadcn/ui** (Radix-based components)
- **Recharts** (through shadcn chart components) for charts
- **openapi-typescript** + **openapi-fetch** for the typed API client
- **Zod** for env and form validation
- Quality: **ESLint** (flat config, run via `eslint`, not `next lint`), **Prettier**,
  **Vitest** + **React Testing Library**

### Where does code go?
- Used by **one feature** → `features/<feature>/…`
- Used by **two or more features** → `components/` or `lib/`
- A **route** file (`app/**/page.tsx`) only reads params, calls feature functions, and
  composes feature components. No business logic, no direct API calls.

## Data and API rules
- **All API types come from `lib/api/schema.ts`.** Never hand-write a type that mirrors
  a backend response. After any backend change: `make gen-api`, then fix type errors.
- The API client is **server-only** (`import "server-only"` in `client.ts`). It uses
  `API_URL`, which is not exposed to the browser. Do not create `NEXT_PUBLIC_API_URL`.
- Fetch data in **Server Components** through `features/<x>/api.ts`. Each function there
  wraps one endpoint and handles the error shape `{ error: { code, message } }` in one place.
- **Mutations** (e.g. "generate recommendations") use **Server Actions** in
  `features/<x>/actions.ts`, then `revalidatePath` the affected route.
- **Filters live in the URL** (`searchParams`), so every view is shareable and
  bookmarkable. Do not mirror filter state in React state.
- In Next.js 16, `params` and `searchParams` are **Promises** — always `await` them.
  Parse them with a Zod schema before use.
- If request interception is ever needed, use `proxy.ts` (`middleware.ts` is deprecated).

## Component rules
- **Server Components by default.** Add `"use client"` only to the smallest leaf that
  needs state, effects, or browser events (a filter dropdown, a chart tooltip).
- One component per file. File names `kebab-case.tsx`; component names `PascalCase`.
- Props are typed with an `interface <Name>Props`. No default exports except where
  Next.js requires them (`page.tsx`, `layout.tsx`, `error.tsx`, …).
- Every data view handles **loading** (`loading.tsx` / `<Suspense>`), **empty**
  (`EmptyState`) and **error** (`error.tsx` / `ErrorState`). No blank screens.
- shadcn/ui files in `components/ui/` are treated as vendor code: wrap or compose them;
  avoid heavy edits so they stay easy to update.
- The React Compiler is enabled: do not add `useMemo`, `useCallback` or `React.memo`
  unless a measured performance problem requires it.

## Formatting and display (DRY)
- Format every number, percentage, date and lift value with `lib/format.ts`
  (`formatCompact`, `formatPercent`, `formatLift`, `formatDate`). Never inline
  `toLocaleString` or `toFixed` in components.
- Metric labels and colors come from one map in `features/analytics/` — not repeated
  per chart.
- **Competitor views never show clicks, reach or saves.** Use the shared
  `PUBLIC_METRICS` constant when building competitor tables or charts.

## Styling
- Tailwind utilities only; merge classes with `cn()`. No inline `style` except for
  dynamic values (e.g. chart colors).
- Design tokens (colors, radius, fonts) are CSS variables in `app/globals.css`. Use
  tokens, never raw hex values in components.
- Responsive by default (mobile → desktop). Support light and dark mode via tokens.

## Language and accessibility
- Captions may be Arabic or English: render caption text with `dir="auto"`.
- Use semantic HTML (`<main>`, `<nav>`, `<table>`), label every input, keep visible
  focus states, and never rely on color alone to convey meaning in charts.

## Sample data
- `SampleDataBanner` in the root layout is shown whenever the backend reports
  `data_source: "seed"` (from `GET /api/v1/meta`). Never remove or hide it in seed mode.

## Testing
- Vitest + React Testing Library for components with logic and for `lib/format.ts`.
- Test behaviour the user sees (text, roles), not implementation details.
- Mock the feature `api.ts` functions, not `fetch`.
